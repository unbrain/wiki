# 📖 宝玉腾讯学堂分享：AI 原生思维——像训练大模型一样训练自己

> [!abstract] 一句话概括
> 宝玉（@dotey）在腾讯学堂的内部分享，以自己做三年的字幕翻译 App（BaoCut）为主线，完整讲了一遍 AI 产品从**找需求 → 判边界 → 最小验证 → 重设计 → 落地交付**的方法论，问答部分回答个体如何与 AI 共同进化。核心暗线：**建立反馈循环 → 跟着模型一起进化 → 敢于推翻自己的旧答案**，就像训练大模型要推翻旧权重。

## 🧭 全文骨架

```
找需求（盯模型能力边界）→ 判边界（能力/成本/价值三关）
→ 最小验证（让坏想法死得早）→ 重设计（不要让 AI 模仿人）
→ 落地五关（流程没变，人的角色变了）→ 个体进化（Loop Engineering）
```

## 一、找需求：盯着模型能力的边界线

- **需求三问**：痛点够不够硬？我是不是自己的用户？AI 是不是刚好够到这个需求？
- **同一个提示词的三级命运**：他的 Nano Banana 城市天气图提示词，早期要手动输一堆城市天气信息无人问津；等 Gemini 内置搜索后简化到只输城市名，立刻火到英文圈、Google CEO 公开致谢。结论：**需求一直都在，是能力边界刚好扫过了它**。
- 模型每次升级（GPT-3 补全 → ChatGPT 对话 → Agent 自主执行），边界线外扩一圈，扫过的地方全是新需求。**在边界线上找机会，最容易。**

## 二、判边界：能力、成本、价值，连闯三关

| 边界 | 关键判断 | 案例 |
|---|---|---|
| **能力** | 想法太早烧的只是 Token；同一个「通用 Agent」想法，AutoGPT（2023）凉了，Manus 火了——差别只在能力是否刚好够到 | Claude Code 用最简单的命令行循环成为最火 Coding Agent：**形态服务于能力，不服务于潮流** |
| **成本** | 公式 = 调用次数 × 单次 Token 量 × 单价，三个因子都要动 | 真实优化：结构化 JSON 改纯文本/HTML 输出 + 便宜模型翻译 + diff 算法解析，调用 33→12 次，单集处理 31→18 分钟 |
| **价值** | 用户买的是结果还是结果背后的人？这条线锚在人性上，**不随模型升级移动** | 字幕翻译用户只要确定性结果；AI 写小说/做视频则天然被抵触为「AI 垃圾」 |

**产品三问**（落地为操作规则）：现在能做的马上做；半年后能做的搭架子等模型（模型进化是你的顺风）；很久做不了的用工程补，或者别做。

## 三、最小验证：让坏想法死得早

- BaoCut 差点进「半成品坟场」，靠两个选择救活：
  1. **Claude Design 高保真原型**：不写代码，配模拟数据，几分钟上手测试，反馈周期从几天压到几小时；
  2. **用不熟的 Swift + AppKit**：因为不熟才能放手交给 AI，自己只管验收。*在不熟悉的领域开始，反而更接近 AI 原生思维。*
- 反例：用 AI 一小时做的推特客户端原型，漂亮但「没有每天想用的冲动」——砍掉。**最小验证的另一面就是让坏想法死得早。**

## 四、重设计：不要让 AI 模仿人（全文最核心）

- **V1 的错误**：模拟字幕组流程（听写→翻译→人工校对→对轴），旧框架里打补丁，收益递减。
- **V2 的方法**：以终为始，连追三个「为什么」——为什么对不齐（改用 Whisper 词级时间戳，句子对齐后按词重拆）、为什么翻译质量差（先提取术语表按页注入）、为什么这么多人工（每步给 Agent 验证工具，人只兜底）。
- **三条设计准则**：
  1. 让 Agent 操作它最擅长的格式（HTML/Markdown/纯文本，训练数据里管够）；
  2. **给设计规范，不给模板**——模板是专家捷径，规范加模型能力终将胜出（「苦涩的教训」），且模型升级时产品不改代码自动变强；
  3. **把 App 做成 Agent 的插件**——购买决策已发生在 Agent 对话里，你的详情页只是 Agent 的数据源。
- 最诚实的信号：**作者本人都不打开自己的 GUI 了**，Codex 里丢个视频链接一句话翻完。入口已从 App 迁移到 Agent。

## 五、落地五关：流程没变，人的角色变了

- 固定流程：可行性 → 设计文档 → 高保真原型 → 实现（拆里程碑）→ 测试。AI 原生开发里**文档是一等公民**：对人是确认载体（改文档比改代码便宜），对 Agent 是 Session 间传上下文的接力棒。
- 角色转变：从程序员变成「产品经理 + 测试 + 管理者」。**验证题给 Agent，判断题留给人**——人只答「方向对不对、体验好不好、值不值得做」。
- 瓶颈转移：Agent 几小时写完码，左边设计确认、右边测试部署还是人类速度。**精力花在流程设计上比优化 Prompt 值得。**

## 六、问答精华：个体如何与 AI 共同进化

- **反馈循环**：小循环做项目（定义 → AI 执行 → 验收），大循环做分享（费曼学习法，输出倒逼系统思考）。「把人的成长做成一套 Loop Engineering。」
- **分工**：执行层交给 AI 不用有心理负担；把自己当 Tech Lead，AI 是员工。人的价值在两头——**定义问题靠练习，验收结果靠品味**。
- **品味**：像模型的监督微调，靠大量输入 + 自己上手，好坏一对比品味就出来了。AI 短期替代不了。
- **Vibe Coding 验收**（反直觉观点）：不用太在意代码整洁和过度防御，把自己当 QA，只把三件事——**功能完整、性能可跑、安全（最高优先级）**。真正重点是拆分（拆成 Agent 刚好能处理的小模块）和验收。
- **老项目改造**：维护 AGENTS.md 当地图 + 每次变更同步更新文档 + 让 Agent 能自己验证（补集成测试，警惕 AI 为过测试而写测试）。

## 💡 我的提炼

1. **三条线的框架最值得收藏**：能力线会动、成本线会动、价值线锚在人性上不动——机会在前两条线上找，护城河在第三条线内侧建。
2. 「不要让 AI 模仿人」与当日早报的 [[2026-09-01-早报|LoopArena 基准]] 形成互证：评测/设计的对象都在从「人的流程」转向「循环本身」。
3. 「给规范不给模板」「入口迁移到 Agent」「文档是给 Agent 的接力棒」三条对本文知识库（Quartz + Obsidian）的写作流程同样适用。
4. 文中的成本优化案例（33→12 次调用）是「模型输出简单格式、复杂解析交给程序」的教科书式取舍。
